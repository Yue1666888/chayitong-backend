# 茶一统后端需求规格

## 1. 目标

为茶一统微信小程序提供完整、可持久化、可授权、可测试的 HTTP 后端，替换纯前端项目中的本地数据、模拟用户、模拟社区和模拟商城流程。系统以模板项目为工程骨架，覆盖内容浏览、个性化推荐、用户资产、社区互动、商品交易和文件上传。

## 2. 用户与角色

- **访客**：浏览已公开的茶、文章、商品和公开社区内容，使用公开搜索和推荐。
- **登录用户**：维护本人资料、收藏、浏览历史、帖子和购物车，创建订单并查看本人订单。
- **内容/系统管理员**：维护茶、文章、商品及其上架状态，处理需要后台管理的内容。管理接口不依赖客户端传入角色。
- **外部身份**：微信小程序用户通过微信登录凭证换取服务端会话；微信 `openid` 等标识不直接作为对外业务主键。

## 3. 功能范围

### 3.1 认证与用户

- 微信登录、访问令牌续期/退出、当前用户查询。
- 用户昵称、头像、地区等资料维护。
- 收藏、浏览历史、我的帖子均严格按登录身份隔离。
- 收藏、点赞等反向操作必须幂等；历史记录去重并更新最近浏览时间。

### 3.2 茶与文章内容

- 茶分类、名茶列表、筛选、搜索和详情。
- 文章列表、栏目/标签/关键词筛选、详情和结构化管理内容。
- 首页和百科需要的数据由公开内容接口提供；下架、草稿和已删除内容不得公开泄露。
- 推荐与答题基于已发布内容，规则可解释、结果可重复验证，不使用无法持久化的随机进程状态。

### 3.3 社区

- 公开帖子流、帖子详情、发布本人帖子、本人帖子列表。
- 点赞及计数、评论及楼层/时间顺序等前端实际需要的互动。
- 作者只能修改或删除自己的帖子；删除后处理详情、列表和互动计数的一致性。
- 图片引用已上传且属于当前用户的文件，不接收任意本地路径冒充远程资源。

### 3.4 商城

- 商品列表、分类/筛选、商品详情和上下架。
- 本人购物车增删改、选中状态与结算汇总。
- 从服务端购物车或明确商品创建订单，服务端重新计算金额并保存商品快照。
- 订单列表、详情、待支付取消及支付结果查询。
- 原前端的模拟支付只作为显式开发能力；生产支付必须通过真实微信支付适配器，不能以客户端“支付成功”直接修改订单。

### 3.5 文件

- 登录用户上传小程序允许的图片，校验大小、扩展名和实际内容类型。
- 返回可持久化的文件 ID、访问 URL 和元数据；业务内容只引用服务端文件。
- 本地开发、腾讯云 COS 与 S3 兼容对象存储通过统一接口隔离；生产默认使用 COS，不得依赖应用单机临时目录。

## 4. 跨模块业务规则

- 公开接口只返回公开状态数据；私有接口从认证上下文取得用户 ID，忽略请求中冒用的用户 ID。
- 所有列表使用统一分页结构，`pageNum` 从 1 开始，`pageSize` 有上限；稳定排序避免翻页重复或遗漏。
- 删除采用模板逻辑删除约定。已被订单引用的商品和已被内容引用的媒体不得因后续修改破坏历史快照。
- 多表写入使用事务；唯一约束与业务校验共同保证幂等，不能只依赖先查后写。
- 统一响应包含业务码、消息、数据、时间戳和 trace ID；错误同时使用正确 HTTP 状态。
- 敏感配置仅来自环境变量，日志不记录密码、令牌、微信凭证或完整隐私数据。

## 5. 非功能需求

- Java 25、Spring Boot 4.1.2、MyBatis-Plus 3.5.18、MySQL 8.x，Maven Wrapper 构建。
- 模块按 `controller/service/mapper/entity/request/response/assembler` 分层，禁止 Controller 直接访问数据库。
- 自动化测试覆盖公开可见性、身份权限、输入校验、分页、幂等、事务和关键状态机。
- 标准 `test` 与 `clean package` 可重复执行；最终使用隔离的真实 MySQL 做完整验收。
- 数据库结构由版本化 SQL 管理，应用启动不隐式建表或修改生产数据。
- 提供健康检查、OpenAPI 可选开关、CORS、trace ID 和容器化运行配置。

## 6. 明确边界

- 不实现与小程序无关的通用后台前端页面。
- 不保留旧项目的课堂演示接口、示例 CRUD、广播 WebSocket 或仅为教学存在的端点。
- 不承诺在无微信商户号、证书和回调域名时完成真实资金扣款；该外部条件单独列入验收限制。
- 内容推荐首版采用确定性规则，不引入机器学习平台、Redis、消息队列等非必要基础设施。
