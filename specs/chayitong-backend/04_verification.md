# 验证与最终验收

本文先定义验收标准，实施后记录实际命令、环境和结果。计划项不得写成已通过。

## 1. 自动验证门槛

- Maven Wrapper 的全量测试无失败、无错误。
- `clean package` 成功生成应用 JAR。
- 测试覆盖每个模块的正常路径，以及未认证、越权、资源不存在、参数错误和状态冲突。
- 收藏、点赞、购物车写入、订单创建等关键操作验证重复请求和并发约束。
- 测试数据与本地已有数据库隔离，不清空或覆盖用户现有数据。

## 2. 真实 MySQL 验收

- 使用全新隔离数据库执行 `sql/bootstrap/init.sql` 和必要的种子脚本。
- 核对表、唯一约束、外键/等价一致性约束和索引。
- 使用生产 profile 的必需环境变量启动，但仅在开发验收环境开启演示支付。
- 通过实际 HTTP 请求而非只调用 Service 验证序列化、安全过滤器和状态码。

## 4. 外部能力验收限制

真实微信登录需要有效小程序凭证；真实微信支付还需要商户号、API 密钥/证书、回调地址和对账配置。缺少这些条件时，可用受控测试替身验证本系统边界，但必须单独标记“未做真实第三方资金验收”，不得记为真实支付通过。

## 6. 最终结论与边界

- 文档内业务模块、标准测试、打包、真实 HTTP 主流程和管理员场景均已通过。
- 微信登录验收使用独立 HTTP 测试替身，已验证本系统登录、令牌和权限边界；未使用真实小程序 AppID/AppSecret 做腾讯侧联调。
- DEMO 支付已验证，且关闭开关和真实渠道不可用均有测试；未配置微信商户、证书和回调，因此未做真实资金验收，预留通知接口固定返回 503。
- 媒体 LOCAL、上传校验、外链迁移和读取已验收；未对真实 S3 服务做外部联调，S3 缺配和降级保护有测试。
- 临时应用、微信替身和数据库容器已停止；隔离数据卷保留，未清空或覆盖旧项目数据库。
