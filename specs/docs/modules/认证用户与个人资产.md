# 认证、用户与个人资产模块

## 1. 身份模型

纯前端没有真实登录，默认本地用户可写全部数据。新后端引入微信小程序登录，同时保持公开内容免登录。

- 客户端用 `wx.login` 的一次性 code 调用 `POST /api/auth/wechat/login`。
- 服务端通过受控 HTTP 客户端调用微信 `jscode2session`，验证返回并只保存 appid+openid 对应关系。
- openid、session_key、AppSecret 不进入 API 响应或日志；业务用户 ID 与 openid 分离。
- 首次有效登录自动创建用户，同一微信身份重复登录只对应一个用户。
- 使用服务端生成的高强度 opaque token，不以可伪造用户 ID 或自行设计 JWT 代替认证。
- 数据库仅保存访问/刷新令牌的 SHA-256 摘要、用户、过期时间和撤销时间；原始令牌仅登录/刷新响应返回。
- 访问令牌短期有效，刷新令牌长期有效并可轮换；退出撤销当前会话。过期/无效令牌统一 401。
- 角色为 USER/ADMIN，管理员来源只能是受控数据库变更，不接受请求指定角色。

## 2. 资料与个人中心

- `GET /api/me` 返回本人资料及等级；`PATCH /api/me/profile` 支持 displayName、avatar、bio、favoriteTea 部分修改。
- 昵称 trim 后非空，按 Unicode 码点最多 12；签名 trim 后可空，最多 24 码点。
- 常喝茶只能是 `绿茶/白茶/黄茶/青茶/红茶/黑茶/不挑，都喝` 或空。
- avatar 只能引用当前用户已上传且用途为 avatar 的媒体；不接受 wxfile 或本机临时路径。
- `GET /api/me/summary` 返回收藏数、足迹数、本人可见动态数、积分和等级，计数实时与列表口径一致。
- points、level、lastDailyAt 只能由服务端计算，客户端额外传入无效。

## 3. 每日积分与等级

- `POST /api/me/daily-points` 按 Asia/Shanghai 业务日期领取 5 分。
- `(user_id, rule_code, business_date)` 唯一约束；同日串行或并发重复请求只加一次，响应 awarded=false。
- 发帖、点赞、评论积分在原前端没有实际执行，首版不自动增加，避免引入刷分。
- 九级门槛：0、100、250、450、700、1000、1400、2000、3000。
- 等级名：初识茶味、闻香识茶、一盏知春、茶席常客、辨味识韵、壶中岁月、茶事精进、通晓茶性、茶中博士。
- 等级响应含当前索引/名称/说明/积分、下一级名称和门槛、剩余积分、百分比和是否封顶；3000 后进度 100%。

## 4. 收藏

- 目标类型正式支持 `tea/article/product/post`；前端没有入口的类型仍由统一后端契约支持。
- `PUT /api/me/favorites/{type}/{id}` 表达收藏，`DELETE` 表达取消，重复调用均幂等，不使用 toggle。
- 新收藏必须引用当前公开可用目标；唯一约束 `(user_id,target_type,target_id)`。
- 列表支持类型筛选和统一分页，按 `createdAt DESC,id DESC`，解析目标摘要。
- 目标下架/删除后记录保留，列表项 `available=false` 且不返回非公开详情；个人中心收藏数与列表 total 均统计未删除收藏，失效占位也计入。
- 操作响应包含 active 和有效收藏总数；取消不影响目标内容。

## 5. 浏览历史

- 目标类型同收藏。客户端在公开详情成功展示后显式 `PUT /api/me/history/{type}/{id}`，公开 GET 不隐式写历史。
- 新记录校验目标公开可用；同目标重复浏览更新 viewedAt 并移动到最前，不新增重复行。
- 每用户全类型最多 50 条，写入与淘汰最旧记录在同一事务完成。
- 列表按 `viewedAt DESC,id DESC`，支持类型筛选和分页；失效目标同样以 available=false 展示。
- 单条删除和 `DELETE /api/me/history` 清空均幂等；清空只影响历史，不影响收藏、帖子或目标内容。

## 6. 权限与缓存

- 所有 `/api/me/**` 接口只操作认证用户，不提供可通过 userId 查询他人资产的别名接口。
- 退出和账号切换时前端清理私人缓存；本机“清除数据”不删除服务端账号、动态或评论。
- 离线队列使用 clientRequestId 或目标最终状态同步；网络失败不能在本地伪造云端成功。
- 公开接口携带有效令牌时可附加 liked 等私有视图；无效令牌按 401 处理，而不是静默当游客。

## 7. 接口范围

- 认证：`POST /api/auth/wechat/login`、`POST /api/auth/refresh`、`POST /api/auth/logout`。
- 本人：`GET /api/me`、`PATCH /api/me/profile`、`GET /api/me/summary`、`POST /api/me/daily-points`。
- 收藏：`GET /api/me/favorites`、`PUT/DELETE /api/me/favorites/{type}/{id}`。
- 历史：`GET /api/me/history`、`PUT/DELETE /api/me/history/{type}/{id}`、`DELETE /api/me/history`。

## 8. 验收

1. 无效微信 code 401；有效 code 首次创建、再次复用同一用户；响应和日志不泄露微信秘密。
2. 令牌认证、过期、刷新轮换和退出撤销正确；伪造 userId/openid/points 不改变身份和资产。
3. 资料长度与枚举边界正确，普通用户不能调用管理接口。
4. 每日积分同日并发只加 5，跨日可再领，所有等级门槛与封顶正确。
5. 收藏重复添加/取消幂等，目标失效后列表和汇总口径一致。
6. 历史去重、更新时间、50 条淘汰、单删和清空正确，用户之间完全隔离。
