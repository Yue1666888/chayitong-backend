# 商城与订单模块

## 1. 现状与目标

纯前端商城包含 30 条商品种子、多规格、购物车、结算、订单和演示支付，但购物车与订单主要存于本机，云函数也信任客户端商品快照并直接写成已支付。新后端必须把商品、库存、计价、归属、订单状态和幂等收回服务端。

首版履约方式沿用“到店自取”，配送费为 0，不采集收货地址。优惠券、物流、退款和售后不在首版范围。

## 2. 商品与规格

- 游客可查询在售商品和详情；下架、草稿、删除商品公开返回 404。
- 筛选项：`categoryId`、`teaId`、`keyword`、`featured`；默认按 `sort` 升序、ID 稳定次序，再分页。
- 商品字段：ID、编码、分类、主关联茶、关联茶集合、名称、副标题、封面、图集、标签、结构化详情、精选标记、排序和状态。
- 商品与规格一对多。规格字段：ID、名称、SKU 编码、售价、划线价、启用、默认、在手库存、预占库存和版本。
- 金额一律为整数分，`originalPriceFen >= priceFen >= 0`；库存不得为负，可用库存为 `stockOnHand - stockReserved`。
- 列表展示默认可用规格价格；详情只暴露启用规格。订单保存商品和规格快照，不随商品后续修改而变化。
- 商品详情块与文章共享受控块模型；管理接口仅管理员可用。

## 3. 购物车

- 所有购物车接口要求登录，用户 ID 只来自认证上下文。
- 服务端购物车行使用自己的 Long ID；同一用户、商品、规格唯一。
- 加购表示追加数量并自动勾选；重复加购合并。数量范围 1～99，且不得超过可用库存。
- 修改数量、勾选、全选/全不选、移除和清空均返回最新购物车。
- 购物车不锁库存。读取时按当前 SKU 重算单价、小计和勾选总额。
- 下架、停用或无库存项不得静默消失，响应保留该项并给出 `invalidReason`，且不能结算。
- 汇总字段：`items`、`checkedCount`、`totalFen`、`cartCount`。

## 4. 结算与订单创建

- 结算输入只包含购物车行 ID 和自提信息，不接受商品名、单价、小计或总额。
- 服务端重新校验上下架、规格、数量和库存并计算：商品总额、配送费 0、优惠 0、应付总额，币种 CNY。
- 报价带过期时间；创建订单时再次校验。价格或库存变化时返回冲突，不沿用旧报价。
- 创建订单要求非空选中项，并在单个数据库事务内创建订单、订单项快照、原子预占库存和处理购物车。
- 创建后状态为 `PENDING_PAYMENT`，支付状态 `UNPAID`，履约状态 `NOT_STARTED`。
- 购物车只扣除本次成交数量；下单期间新增数量不得被误删。
- 首版下单不增加积分，避免把原前端的本地奖励演示扩张为未经设计的资产系统。

## 5. 状态机

### 订单

- `PENDING_PAYMENT → PAID`：可信支付成功。
- `PENDING_PAYMENT → CANCELLED`：本人主动取消。
- `PENDING_PAYMENT → CLOSED`：超时或系统关单。
- 已支付订单首版不提供用户取消；取消/关单只发生一次并释放预占库存。

### 支付

- `UNPAID → PAYING → PAID`；失败可重新发起，关闭后不可支付。
- 真实微信支付以验签通知或主动查单为准，不能以小程序 success 回调改状态。

### 自提履约

- 待支付为 `NOT_STARTED`；支付后为 `PENDING_PICKUP`；管理员核销后为 `COMPLETED`。
- 首版可以实现管理核销，但不扩展物流和售后。

## 6. 支付边界

- `DEMO` 支付仅在显式配置开关下可用，订单永久标记 `paymentMode=DEMO`，响应明确“演示订单，不产生真实扣款”。
- 生产默认关闭 DEMO；未配置真实微信支付时返回能力不可用，不得自动降级为演示成功。
- 支付单与订单分离，保存渠道、金额、状态、服务端支付号、第三方交易号和时间。
- 第三方交易号唯一；重复或乱序通知不得重复扣库存、重复释放或使已支付状态倒退。
- 真实微信资金验收依赖商户号、证书和回调配置，不能以演示支付替代。

## 7. 幂等与并发

- 创建订单必须携带 `clientRequestId`，数据库唯一约束 `(user_id, client_request_id)`。
- 同用户、同键、同请求返回首次订单；同键不同请求返回 `IDEMPOTENCY_CONFLICT`。
- 请求指纹基于规范化购物车行/数量、自提和备注，不包含客户端金额。
- 库存预占使用事务内行锁或条件更新，两个用户购买最后一件时只能一个成功。
- 订单号、支付交易号均有唯一约束；异常响应后客户端用同幂等键重试，不生成本地第二单。

## 8. 接口范围

- 公开：`GET /api/products`、`GET /api/products/{id}`。
- 管理：`POST/PUT /api/admin/products`、`PUT /api/admin/products/{id}/status`。
- 用户购物车：`GET /api/cart`、`POST /api/cart/items`、`PATCH/DELETE /api/cart/items/{id}`、`PUT /api/cart/selection`、`DELETE /api/cart`。
- 用户交易：`POST /api/checkout/quote`、`POST /api/orders`、`GET /api/orders`、`GET /api/orders/{orderNo}`、`POST /api/orders/{orderNo}/cancel`。
- 支付：`POST /api/orders/{orderNo}/payments`、`GET /api/orders/{orderNo}/payment-result`；真实微信通知作为独立验签端点预留。
- 自提核销：`POST /api/admin/orders/{orderNo}/pickup-completion`。

详细输入输出见 `specs/docs/API接口文档.md`。

## 9. 模块验收

1. 游客只见在售商品，规格价格和筛选正确。
2. 重复加购合并，数量/勾选/合计正确，失效项有明确原因。
3. 伪造 0 元或客户端快照不影响服务端订单金额。
4. 空订单、超库存、报价变化均被拒绝且事务完整回滚。
5. 同幂等键串行/并发只创建一单；不同内容复用键返回 409。
6. 商品修改后历史订单快照不变，只清理成交购物车数量。
7. 用户不能读取、取消或支付他人订单，越权按资源隐藏规则返回 404。
8. 取消释放一次库存；演示支付有明确标记且生产关闭。
9. 真实微信伪造通知、金额不符、重复通知在具备适配器后必须有专项测试；未具备外部条件时记录未验收项。
