# 后端架构与工程约定

## 1. 技术栈

Java 25、Spring Boot 4.1.2、Spring MVC、Spring Security、MyBatis-Plus 3.5.18、MySQL 8、Springdoc OpenAPI、Maven Wrapper、Docker Compose。测试使用 JUnit、MockMvc 和 Testcontainers MySQL。

## 2. 仓库布局

```text
chayitong-backend/                 # 外层仓库与部署入口
├── chayitong-backend/             # Maven 应用
│   ├── src/main/java/com/chayitong/
│   ├── src/main/resources/
│   ├── src/test/java/com/chayitong/
│   ├── sql/{bootstrap,schema,migrations,maintenance}/
│   ├── pom.xml
│   └── mvnw*
├── specs/chayitong-backend/       # 总体规格、设计、任务、验收
├── specs/docs/                    # API、架构、数据库和模块文档
├── compose*.yaml
└── Dockerfile
```

根包 `com.chayitong`。业务包使用单数小写名称，内部遵循模板的七层目录。请求、持久化和输出模型分离，实体不直接作为 API 响应。

## 3. 核心约定

- REST 路径 `/api/` + 小写复数，多词用短横线；本人资源使用 `/api/me/**`，管理资源 `/api/admin/**`。
- 响应 `CommonResponse<T>`，分页 `PageResponse<T>`，错误由 BusinessException/ErrorCode 和全局异常处理器统一。
- 主键 BIGINT 雪花 ID，API 序列化为字符串；内容稳定字符串 ID 通过 business_key 保存。
- created_at/updated_at 自动填充，deleted=1 逻辑删除；关系表是否继承 BaseEntity 按业务需要，不为点赞伪造无意义逻辑删除。
- SQL 手工/部署执行，应用不自动建表；完整结构和增量迁移职责分离。
- 所有分页有上限与稳定次序，所有写接口有参数、身份、权限和幂等/冲突规则。

## 4. 配置分组

| 配置 | 说明 |
| --- | --- |
| `DB_URL/DB_USERNAME/DB_PASSWORD` | 数据库连接，生产无默认密码 |
| `SERVER_PORT` | 默认 8080 |
| `APP_CORS_ALLOWED_ORIGINS` | 管理 Web 前端等允许来源，小程序请求不依赖 CORS |
| `WECHAT_MINIAPP_APP_ID/APP_SECRET` | 微信登录服务端凭证 |
| `APP_TOKEN_ACCESS_TTL/REFRESH_TTL` | 令牌有效期 |
| `APP_MEDIA_STORAGE` | local 或 s3 |
| `APP_MEDIA_LOCAL_ROOT` | dev/test 本地媒体目录 |
| `APP_COS_*` | 生产默认 COS 的 secretId、secretKey、region、bucket、prefix |
| `APP_MEDIA_S3_*` | 可选 S3 的 endpoint、region、bucket 和凭证 |
| `APP_SHOP_QUOTE_SECRET` | 报价 HMAC 密钥，至少32字节，生产必须显式配置 |
| `APP_SHOP_DEMO_PAYMENT_ENABLED` | 演示支付开关，生产默认 false |
| `SPRINGDOC_*` | OpenAPI/Swagger 开关，默认关闭 |

配置通过 `@ConfigurationProperties` 绑定和校验。秘密只从环境变量或受控密钥系统注入，不写入 specs、源码、SQL 种子或日志。

## 5. 安全边界

- 微信 code 交换、Bearer token 摘要、刷新轮换、撤销和角色检查构成认证链。
- 公开查询只读发布/在售状态；私有资源按当前用户归属；管理员能力使用 ROLE_ADMIN。
- 无状态 Bearer 不使用 Cookie/CSRF；HTTP Basic、JSESSIONID 和旧教学注册接口全部移除。
- 上传限制类型和大小；CORS 精确配置；默认错误不泄露内部细节。
- 支付和积分只能由服务端可信事件改变。

## 6. 事务与性能

- Service 默认只读事务，写方法显式 `@Transactional`。
- 点赞/评论计数、订单/库存/购物车、积分流水/余额、媒体绑定必须在同一事务。
- 列表覆盖状态+排序、用户+时间、唯一业务键等索引；文章正文和商品详情不在列表重复解析。
- LIKE 搜索为首版小规模方案；后续全文检索是独立优化，不影响接口契约。
- 不使用进程内缓存保存权威用户资产、订单、互动或令牌，保证多实例可迁移。

## 7. 运行与验证

开发：启动隔离 MySQL，执行 bootstrap SQL，再运行 `./mvnw spring-boot:run`。测试：`./mvnw test`，Testcontainers 自建 MySQL。打包：`./mvnw clean package`。容器：`docker compose up --build -d`，初始化挂载只在新卷执行。

最终验收使用真实 HTTP 请求覆盖规格 E01～E10。现有 `D:/docker-data/chayitong/mysql` 与 storage-data 不被测试或新 Compose 自动清理。真实微信支付和微信内容审核需要外部账号与配置，单独记录验证状态。
