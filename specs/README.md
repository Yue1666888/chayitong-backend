# 茶一统后端规格说明

本目录是后端实现与验收的唯一业务基线。业务来源为 `02-chayitong` 纯前端小程序，工程约束来源为 `java-web-zy-template/template`。旧后端仅用于核对已有决策，不作为新实现兼容约束。

## 文档结构

- `chayitong-backend/01_spec.md`：总体范围、角色、业务规则和非功能需求。
- `chayitong-backend/02_design.md`：架构、认证授权、数据一致性、文件与外部服务设计。
- `chayitong-backend/03_tasks.md`：按依赖顺序拆分的实施任务及完成标准。
- `chayitong-backend/04_verification.md`：自动测试、MySQL 验收和端到端场景记录。
- `docs/API接口文档.md`：统一契约和各模块 HTTP 接口。
- `docs/后端架构.md`：代码分层、配置、部署与运维约束。
- `docs/数据库设计/MySQL设计-chayitong.md`：表、字段、索引、约束和迁移说明。
- `docs/modules/`：各业务模块的需求、规则与模块验收标准。

## 实施纪律

1. 先完成规格、接口和数据库设计，再编写对应模块代码。
2. 页面展示所需但纯前端硬编码的数据，应明确选择服务端内容或客户端展示常量，不以隐式 mock 代替后端能力。
3. 所有写操作明确身份、权限、参数校验、事务和幂等规则。
4. 金额使用整数分，时间使用 ISO 8601，主键和分页遵循模板统一约定。
5. 不把演示支付、假微信登录、进程内数据或本地文件返回伪装成生产能力。
6. 每完成一个模块，更新任务和验证记录，并运行该模块测试及全量回归。
